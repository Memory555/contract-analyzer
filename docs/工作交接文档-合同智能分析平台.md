## 1. 项目概述

合同智能分析平台是一款基于大语言模型的合同审查工具。用户上传合同文件（DOCX/DOC/PDF/图片），系统自动提取文本并调用大模型生成结构化分析结果，包括**合同问题清单、付款计划、质保明细**等，支持单合同分析和多合同批量处理，结果可导出为 Excel。

### 1.1 核心能力

| 能力 | 说明 |
|------|------|
| 多格式解析 | 支持 DOCX、DOC、PDF、JPG、PNG 五种格式 |
| DOC 转换 | 通过 LibreOffice 将旧版二进制 DOC 转为 DOCX 再解析 |
| 扫描件 OCR | PDF 无文本层时自动走腾讯云 OCR 识别 |
| 大模型分析 | 调用 LLM（DeepSeek / OpenAI 兼容）生成结构化审查结果 |
| 批量处理 | 一次最多上传 20 份合同，串行分析 |
| Excel 导出 | 单合同和批量汇总两种导出模式，含多个 Sheet |
| 反馈系统 | 用户对分析结果评分/评论，数据写入 PostgreSQL |
| 演示模式 | 模型不可用时返回模拟数据，方便流程验收 |

## 6. 本地开发指南

### 6.1 环境要求

| 工具 | 最低版本 | 说明 |
|------|---------|------|
| Node.js | 20+ | 前端运行 |
| Python | 3.11+ | 后端运行 |
| Docker | 24+ | 容器构建（可选用） |

### 6.2 前端启动

```bash
cd frontend
npm install
npm run dev
# 访问 http://localhost:3000
```

### 6.3 后端启动

```bash
cd backend
pip install -r requirements.txt

# 需要设置环境变量
export OPENAI_API_KEY=sk-xxx
export OPENAI_BASE_URL=https://api.deepseek.com/v1
export OPENAI_MODEL=deepseek-chat

uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
# 健康检查：http://localhost:8000/api/health
```

### 6.4 构建验证

```bash
# 前端
cd frontend && npm run build

# 后端（Docker 构建）
cd backend && docker build -t contract-analyzer-backend:v6 .
```

### 7.1 CloudBase 部署更新

1. 代码推送到 GitHub
2. CloudBase 云托管 → 版本管理 → 新建版本
3. 选择对应分支 → 开始构建
4. 构建完成后配置流量比例 → 发布

详细步骤见 [v6部署交付文档.md](https://github.com/Memory555/contract-analyzer/blob/v6/docs/v6%E9%83%A8%E7%BD%B2%E4%BA%A4%E4%BB%98%E6%96%87%E6%A1%A3.md)。

### 7.2 数据库维护

Neon PostgreSQL 为托管服务，日常无需运维。如需进入数据库：

```bash
psql "postgresql://user:password@host:5432/database"
```

主要表：`analysis_feedback`（反馈数据）。

### 7.3 紧急处理

| 场景 | 处理方式 |
|------|---------|
| 前端页面打不开 | 检查 CloudBase 前端服务状态和日志 |
| 分析失败 | 检查 DeepSeek API 余额和配额 |
| DOC 转换失败 | 确认后端容器内 LibreOffice 可用 |
| OCR 不可用 | 检查腾讯云 OCR 配额（每月 1000 次免费额度） |
| 数据库连接失败 | 检查 Neon 项目状态和 IP 白名单 |

## 8. 已知限制与注意事项

| # | 限制 | 说明 | 影响 |
|---|------|------|------|
| 1 | 批量分析为串行 | 稳定优先，速度与合同数量线性相关 | 20 份合同可能需要较长时间 |
| 2 | 仅支持 DOCX/DOC/PDF/图片 | 不支持 TXT、HTML 等纯文本合同 | 需引导用户转换格式 |
| 3 | 文件大小限制 20MB | 后端和 CloudBase 双重限制 | 大文件需拆分 |
| 4 | 失败重试需重新选择文件 | 浏览器不长期保存 File 对象 | 用户体验稍差 |
| 5 | 本地历史仅当前浏览器 | IndexedDB 存储，换浏览器/清缓存会消失 | 反馈数据在 PostgreSQL 不受影响 |
| 6 | CloudBase 请求超时 60s | 单次分析不能超过 60 秒（可异步化） | 长合同分析需走异步模式 |
| 7 | 历史批量导出未打 ZIP | 当前仅交付批量汇总 Excel | 用户需逐份导出 |
| 8 | CloudBase 构建环境代理问题 | 需注意 HTTP_PROXY 变量 | 参考 v6部署交付文档 |

## 9. 未来迭代方向

以下为已知的优化方向，已记录需求但未排入当前版本：

1. **并发分析**：当前串行改为多任务并行，提升批量处理速度
2. **云存储**：接入对象存储（腾讯云 COS）保存上传文件和分析结果
3. **异步任务队列**：解决 CloudBase 60s 超时限制
4. **用户系统**：接入登录鉴权，支持多用户隔离
5. **合同对比**：两份合同条款差异分析
6. **更多格式**：TXT、HTML 合同支持
7. **结果上云**：当前仅在浏览器 IndexedDB，可迁移到 PostgreSQL
