## 2. 功能说明

### 2.1 反馈入口

左侧导航新增“反馈管理”。合同分析页上传、分析、结果展示、导出等主体设计不做重排。

### 2.2 反馈流程

1. 进入“反馈管理”。
2. 选择一个历史合同分析记录。
3. 点击“有帮助”，直接提交正向反馈。
4. 点击“有问题”，进入问题类型选择。
5. 可选填写一句补充说明。
6. 提交后调用 `/api/feedback` 写入 CloudBase 云数据库；浏览器本地仅缓存提交状态。

### 2.3 自动记录字段

系统自动带入以下字段，不要求用户填写：

- 分析时间
- 模型名称
- prompt 版本
- 分析结果摘要
- 风险项数量
- 合同原文

说明：v3 更新后新分析的合同会把合同原文保存到本地历史记录中，用于后续反馈提交。更新前已经存在的旧历史记录可能缺少合同原文，需要重新分析后才能提交反馈。

## 3. CloudBase 部署说明

当前 v3 前端已使用 Next.js standalone 输出，并提供 Dockerfile，适合部署到 CloudBase 云托管。

推荐部署路径：

```text
frontend Dockerfile -> CloudBase 云托管 -> Next.js standalone 服务 -> /api/feedback
```

### 3.1 构建命令

在 `frontend` 目录执行：

```bash
npm ci
npm run build
```

### 3.2 本地生产启动

由于 v3 配置了 `output: "standalone"`，生产容器推荐使用：

```bash
node .next/standalone/server.js
```

本地调试也可以使用：

```bash
npm run start -- -p 3000
```

Next.js 会提示 standalone 推荐入口，但本地验证仍可访问。

### 3.3 环境变量

当前模型分析仍使用：

- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_MODEL`
- `NEXT_PUBLIC_DEMO_MODE`

反馈 API 已接入 CloudBase 数据库写入。部署前需要配置：

- `CLOUDBASE_ENV_ID`：CloudBase 环境 ID
- `CLOUDBASE_FEEDBACK_COLLECTION`：可选，默认 `analysis_feedback`
- `TENCENTCLOUD_SECRETID` / `TENCENTCLOUD_SECRETKEY`：本地或非 CloudBase 运行环境需要；CloudBase 运行环境可使用默认凭据

数据库集合默认命名为：`analysis_feedback`。权限建议设置为服务端写入、管理端读取。

- 编译通过。

## 5. 已知限制

- 旧历史记录可能没有合同原文，无法提交反馈；重新分析后可正常反馈。
- CloudBase 环境变量未配置时，反馈提交会返回失败，不再伪成功保存。
- 反馈记录已经写入 CloudBase 云数据库；浏览器本地 Dexie 仅用于反馈状态缓存。跨设备查看历史分析仍需要后续将分析历史迁移到云端。
