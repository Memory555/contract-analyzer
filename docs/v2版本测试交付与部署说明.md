## 2. 本地启动

进入前端目录：

```bash
cd frontend
```

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

访问：

```text
http://localhost:3000
```

## 3. 环境变量

本地或部署平台需要配置：

```text
OPENAI_API_KEY=你的模型服务 Key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1-mini
NEXT_PUBLIC_DEMO_MODE=true
```

说明：

- `OPENAI_API_KEY` 应配置为部署平台 Secret，不要写入代码。
- `OPENAI_BASE_URL` 可替换为 OpenAI-compatible 服务地址。
- 页面设置中填写的模型配置优先于服务端环境变量。
- 如果 `NEXT_PUBLIC_DEMO_MODE=true`，模型不可用时可返回演示数据，用于流程验收。

## 6. 验收重点

重点确认以下问题：

1. 是否能一次上传多份 DOCX。
2. 单份失败是否不会影响其他合同。
3. 同名合同是否能通过上传序号和合同ID区分。
4. 是否能查看每份合同的独立详情。
5. 是否能在批量任务列表中导出单份合同 Excel。
6. 是否能导出全部合同汇总 Excel。
7. 批量汇总 Excel 是否包含合同区分字段。
8. 导出中心是否能展示最近批次和导出记录。

## 7. 部署说明

### 7.1 Vercel 部署

Vercel 项目配置：

| 配置项 | 值 |
|--------|---|
| Root Directory | `frontend` |
| Install Command | `npm install` |
| Build Command | `npm run build` |
| Output Directory | 默认 |

环境变量配置在 Vercel Project Settings：

```text
OPENAI_API_KEY=...
OPENAI_BASE_URL=...
OPENAI_MODEL=...
NEXT_PUBLIC_DEMO_MODE=false
```

部署后访问 Vercel 分配的域名即可。

### 7.2 Cloudflare Workers 部署

进入前端目录：

```bash
cd frontend
```

构建 Cloudflare 版本：

```bash
npm run cf:build
```

部署：

```bash
npx wrangler deploy
```

非生产分支可使用：

```bash
npx wrangler versions upload
```

Cloudflare 环境变量和 Secret 需要在 Wrangler 或控制台中配置。

注意：OpenNext 官方工具链在 Windows 上可能出现不可预测的打包失败。若本机 `npm run cf:build` 失败但 `npm run build` 通过，建议切换到 WSL/Linux 或直接使用 Cloudflare 的 Linux 构建环境验证。

## 9. 当前已知限制

| 限制 | 说明 |
|------|------|
| 当前只支持 DOCX | PDF / DOC 仍未纳入 v2 当前实现 |
| 批量分析为串行 | 稳定优先，速度与合同数量线性相关 |
| 失败重试需要重新选择文件 | 浏览器不会长期保存原始 File 对象 |
| 独立批量导出未打 ZIP | 当前优先交付批量汇总 Excel |
| 历史记录仅在当前浏览器 | 清理浏览器数据后记录会消失 |

## 10. 交付结论

v2 已完成“单合同分析 → 多合同批量分析 → 全部合同汇总导出”的核心升级。当前版本适合作为内部 Demo 和业务确认版本，用于验证多合同处理流程、Excel 汇总字段和导出中心是否符合实际使用习惯。
