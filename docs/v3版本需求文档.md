# 合同智能分析平台 v3 版本需求文档

版本：v3.0.0  
日期：2026-06-22  
状态：需求修订稿  
基线版本：v2.0.0  
部署方向：CloudBase 云托管

## 1. 版本定位

v3 在现有合同分析能力基础上，正式引入后端能力和效果反馈闭环。反馈模块不改变现有合同分析页面的主体设计，而是在左侧导航增加“反馈管理”，让用户对历史合同分析记录进行反馈。

当前合同分析能力主要围绕示例合同模板设计，现实合同中可能存在格式混乱、条款缺失、补充协议、多版本合同、非常规付款条件、质保表述不完整等情况。v3 的目标不是立即解决所有异常合同，而是先稳定采集用户对历史分析结果的反馈，把真实问题沉淀为后续 prompt 调整、模型策略优化和回归测试样本。

核心闭环：

上传合同 -> 系统分析 -> 形成历史分析记录 -> 进入反馈管理 -> 选择某次历史合同分析 -> 提交反馈 -> 后台保存分析上下文 -> 后续复盘与技术调整

## 2. 版本目标

1. 保持现有合同分析页面主体设计不变。
2. 在左侧导航增加“反馈管理”入口。
3. 支持用户在反馈管理中选择某个历史合同分析记录进行反馈。
4. 支持“有帮助”一键提交。
5. 支持“有问题”后再进入问题类型选择和可选补充说明。
6. 后台自动采集分析时间、模型名称、prompt 版本、分析结果摘要、风险项数量、合同原文。
7. 将反馈数据保存到 CloudBase 后端数据服务，便于后续查看、导出和复盘。

## 3. 本期范围

| 模块 | 本期范围 |
|------|----------|
| 左侧反馈管理入口 | 在现有左侧导航中新增“反馈管理”，合同分析页面主体不改版 |
| 历史分析选择 | 用户从历史合同分析记录中选择某一条进行反馈 |
| 基础反馈操作 | 在选中的历史分析详情中提供“有帮助 / 有问题” |

## 4. 用户反馈原则

v3 反馈设计遵循“合同分析不打扰，反馈流程再进入”的原则。

用户侧路径：

1. 从左侧进入“反馈管理”。
2. 选择某个历史合同分析。
3. 点击“有帮助”，直接完成反馈。
4. 或点击“有问题”，进入问题类型选择。
5. 选择问题类型后，可选填写一句补充说明并提交。

系统不要求用户填写分析时间、模型、prompt、风险数量、合同原文等技术上下文。

## 5. 用户场景

### 5.1 对历史分析给出正向反馈

用户完成合同分析后，进入左侧“反馈管理”，选择该历史分析记录。用户认为付款计划、质保明细和问题提示基本符合预期，点击“有帮助”，系统保存正向反馈和该历史分析上下文。

### 5.2 对历史分析标记问题

用户进入“反馈管理”，选择某个历史合同分析，发现系统漏掉了补充协议中的付款节点。用户点击“有问题”，页面再进入问题原因选择，用户选择“漏了重要条款”，可选填写“补充协议第二页还有尾款约定”。

### 5.3 用户不愿输入文字

用户选择历史分析记录后，只点击“有问题”并直接提交。系统仍保存该次负向反馈，用于后续统计异常比例。

## 6. 功能需求

### 6.1 左侧反馈管理入口

| 项目 | 说明 |
|------|------|
| 触发位置 | 左侧导航，与“合同分析”“导出中心”“设置”同级 |
| 页面原则 | 不改变现有合同分析页面主体布局 |
| 进入后 | 显示历史合同分析列表和选中记录详情 |
| 主要任务 | 让用户对过去某一次合同分析进行反馈 |

验收标准：

- 左侧导航出现“反馈管理”。
- 点击“反馈管理”后，进入历史分析反馈页面。
- 原合同分析页面上传、分析、导出布局不因 v3 反馈模块改版。

### 6.2 选择历史合同分析

| 项目 | 说明 |
|------|------|
| 数据来源 | 本地历史记录或后续云端历史记录 |
| 列表字段 | 合同名称、分析时间、风险项数量、反馈状态 |
| 详情字段 | 分析结果摘要、风险项、付款计划、质保摘要 |
| 反馈状态 | 未反馈、有帮助、有问题 |

验收标准：

- 用户可以从历史记录中选择某个合同分析。
- 选择后右侧展示该分析的摘要和反馈操作。
- 已反馈记录能显示反馈状态。

### 6.3 历史分析一键反馈

| 项目 | 说明 |
|------|------|
| 触发位置 | 反馈管理中的历史分析详情 |
| 默认状态 | 显示“有帮助”“有问题”两个操作 |
| 有帮助 | 点击后直接提交正向反馈 |
| 有问题 | 点击后进入问题原因选择，不在第一步展示全部表单 |
| 重复提交 | 同一历史分析默认只保留最后一次反馈或提示覆盖 |

验收标准：

- 点击“有帮助”后，无需填写内容即可提交。
- 点击“有问题”后，才进入问题类型选择状态。
- 提交成功后，历史记录状态同步更新。

### 6.4 问题类型选择

用户点击“有问题”后，展示问题类型选项。

| 类型 | 说明 |
|------|------|
| 漏了重要条款 | 系统未识别出关键付款、质保、风险或其他条款 |
| 判断不准确 | 抽取内容存在理解偏差或结论不符合合同原文 |
| 风险等级不对 | 风险严重程度过高或过低 |
| 内容看不懂 | 结果描述不清晰、表述难以理解 |
| 其他 | 无法归入以上类型 |

验收标准：

- 用户点击“有问题”后才出现问题类型。
- 用户不选择问题类型也可以继续提交。
- 问题类型保存到反馈记录中。

### 6.5 可选补充说明

| 项目 | 说明 |
|------|------|
| 字段 | comment |
| 必填 | 否 |
| 长度 | 建议 0-500 字 |
| 文案 | “愿意的话，补充一句哪里不对” |

### 6.6 后台自动采集字段

提交反馈时，系统自动记录以下字段：

| 字段 | 说明 |
|------|------|
| analysisTime | 分析完成时间或反馈对应的分析时间 |
| modelName | 本次分析使用的模型名称 |
| promptVersion | 本次分析使用的 prompt 版本 |
| resultSummary | 分析结果摘要 |
| riskItemCount | 风险项数量 |
| contractText | 合同原文 |

合同原文属于敏感数据，反馈集合应仅允许服务端写入和管理端读取。

### 6.7 反馈提交接口

| 项目 | 说明 |
|------|------|
| 建议路径 | /api/feedback |
| 方法 | POST |
| 输入 | 用户反馈动作 + 当前历史分析上下文 |
| 输出 | 提交结果、反馈 ID |
| 存储 | CloudBase 数据库 analysis_feedback 集合 |

建议请求结构：

    {
      feedbackType: "helpful" | "problem",
      problemCategory?: "missing_clause" | "wrong_judgment" | "wrong_risk_level" | "unclear" | "other",
      comment?: string,
      analysisTime: string,
      modelName: string,
      promptVersion: string,
      resultSummary: string,
      riskItemCount: number,
      contractText: string
    }

## 7. 数据模型

建议集合名称：analysis_feedback

    type AnalysisFeedback = {
      id: string;
      sourceAnalysisId: string;
      sourceBatchId?: string;
      feedbackType: "helpful" | "problem";
      problemCategory?: "missing_clause" | "wrong_judgment" | "wrong_risk_level" | "unclear" | "other";
      comment?: string;
      analysisTime: string;
      modelName: string;
      promptVersion: string;
      resultSummary: string;
      riskItemCount: number;
      contractText: string;
      status: "pending" | "reviewed" | "converted_to_case" | "closed";
      createdAt: string;
      updatedAt: string;
    };

## 8. CloudBase 支持判断

CloudBase 可以支持 v3 反馈模块需求。推荐形态：

Next.js 前端与 API -> CloudBase 云托管 -> CloudBase 数据库 analysis_feedback 集合

当前 v3 已具备 CloudBase 云托管方向的基础：

- 前端项目已提供 Dockerfile。
- Next.js 配置已使用 output: "standalone"。
- 反馈 API 可作为 Next.js 服务端接口随应用一起部署。
- 反馈数据可保存到 CloudBase 文档型数据库。

## 9. 安全与隐私要求

1. 合同原文默认仅用于内部复盘和技术优化。
2. 反馈数据不应通过公开前端接口直接查询。
3. 数据库权限应限制为服务端写入、管理端读取。
4. 后续外部正式使用前，应补充用户授权提示或脱敏策略。
5. 日志中避免打印完整合同原文和 API Key。

## 11. 验收清单

- 左侧导航新增“反馈管理”，合同分析页主体不改版。
- 用户可在反馈管理中选择某个历史合同分析。
