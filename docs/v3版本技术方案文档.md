# 合同智能分析平台 v3 技术方案文档

版本：v3.0.0  
日期：2026-06-22  
状态：技术方案初稿  
部署方向：CloudBase 云托管

## 1. 技术目标

v3 的技术目标是在不重构合同分析主流程的前提下，新增“反馈管理”能力：用户从左侧导航进入反馈管理，选择某条历史合同分析记录，对该记录提交“有帮助”或“有问题”的反馈。系统自动带入分析上下文，后端保存反馈数据，为后续技术优化和异常样本沉淀提供依据。

## 2. 改动边界

### 2.1 尽量不动的部分

- 合同分析页主体布局。
- 上传、批量分析、结果展示、导出中心逻辑。
- 现有本地历史记录结构的主要字段。
- 现有模型分析 API `/api/analyze`。

### 2.2 主要新增部分

- 左侧导航新增“反馈管理”。
- 新增反馈管理页面组件。
- 新增反馈类型定义。
- Dexie 本地库新增 `feedbacks` 表，用于本地反馈状态和离线可见性。
- 新增 `/api/feedback`，用于服务端接收反馈并写入 CloudBase 云数据库。
- 新增 v3 交付和部署说明。

## 3. 前端架构

页面枚举扩展为 `analysis | exports | feedback | settings`。导航项新增 `反馈管理`，页面渲染分支新增 `FeedbackManagementPage`。合同分析页主体 JSX 不做结构性改动。

反馈管理页面布局：左侧历史合同分析列表，右侧选中历史分析摘要和反馈流程。

反馈流程：`选择历史记录 -> 有帮助/有问题 -> 问题原因 -> 可选说明 -> 提交`。其中“有帮助”直接提交，“有问题”才进入原因选择。

## 4. 数据模型

新增反馈类型：

```ts
export type FeedbackType = "helpful" | "problem";
export type FeedbackProblemCategory = "missing_clause" | "wrong_judgment" | "wrong_risk_level" | "unclear" | "other";

export type AnalysisFeedbackRecord = {
  id: string;
  contractId: string;
  batchId: string;
  fileName: string;
  feedbackType: FeedbackType;
  problemCategory?: FeedbackProblemCategory;
  comment?: string;
  analysisTime: string;
  modelName: string;
  promptVersion: string;
  resultSummary: string;
  riskItemCount: number;
  contractText: string;
  status: "pending" | "submitted" | "failed";
  createdAt: string;
  updatedAt: string;
};
```

Dexie 新增 `feedbacks` 表：`id, contractId, batchId, feedbackType, problemCategory, status, createdAt, updatedAt`。

## 5. 后端 API

新增接口：`POST /api/feedback`。

职责：校验反馈类型、问题类型、补充说明长度和必要上下文字段；生成服务端反馈 ID；写入 CloudBase 云数据库。

请求结构：

```ts
{
  contractId: string;
  batchId: string;
  fileName: string;
  feedbackType: "helpful" | "problem";
  problemCategory?: FeedbackProblemCategory;
  comment?: string;
  analysisTime: string;
  modelName: string;
  promptVersion: string;
  resultSummary: string;
  riskItemCount: number;
  contractText: string;
}
```

响应结构：`{ feedbackId: string; stored: boolean; message: string }`。

## 6. CloudBase 适配策略

当前 v3 项目使用 CloudBase 云托管方向，推荐将 Next.js standalone 容器部署到 CloudBase。反馈 API 随 Next.js 服务一起部署。

后续接入 CloudBase 数据库时建议：集合名称 `analysis_feedback`；权限为服务端写入、管理端读取；通过 `CLOUDBASE_ENV_ID` 和服务端凭据或 CloudBase 运行时默认凭据连接。

本期实现通过服务端 API 写入 CloudBase 云数据库，避免前端直接访问 CloudBase 数据库。

## 7. 自动上下文生成

- `analysisTime`：历史分析记录 `updatedAt` 或 `createdAt`。
- `modelName`：优先使用设置中的模型名，其次使用环境默认占位。
- `promptVersion`：固定为 `v3-feedback-001`。
- `resultSummary`：由付款计划数量、质保字段数量、风险项数量和置信度生成摘要。
- `riskItemCount`：`result.issues.length`。
- `contractText`：合同分析成功后保存到历史合同记录中，反馈时自动带入。

## 8. 冒烟测试范围

1. 编译通过。
2. 本地 3000 端口启动成功。
3. 左侧导航出现“反馈管理”。
4. 合同分析页主体仍可打开。
5. 反馈管理在无历史记录时展示空状态。
6. 有历史记录时可选择合同并提交“有帮助”。
7. 点击“有问题”后才显示问题原因。
8. 可选填写说明并提交。
9. `/api/feedback` 对非法请求返回 400。
10. 提交成功后本地反馈状态更新。

## 9. 风险与后续

- 历史合同原文属于敏感数据，本期仅服务端保存反馈记录，后续商用前需增加授权提示或脱敏策略。
- 当前 CloudBase 数据库写入需要根据实际环境凭据补齐，本期先完成 API 边界和适配点。
- 若未来要跨设备查看反馈管理，需要把历史分析记录也迁移到云端。
