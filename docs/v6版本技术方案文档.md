# 合同智能分析平台 v6 版本技术方案文档

版本：v6.0.0  
日期：2026-06-30  
适用范围：CloudBase 前端部署、CloudBase 云托管后端、PDF/DOC/DOCX/JPG/PNG 解析、扫描件 OCR、异步任务

## 1. 技术目标

v6 的技术目标是把当前 v5 的轻量前端解析架构，升级为可正式处理多格式合同和扫描件的 CloudBase 双服务架构。

当前 v5 架构：

```text
Next.js 前端
  ↓
浏览器端 mammoth 提取 DOCX 文本
  ↓
Next.js /api/analyze 调用模型
  ↓
IndexedDB 保存历史
```

v6 目标架构：

```text
CloudBase 云托管 frontend-service
  ↓
CloudBase 云托管 backend-service
  ↓
CloudBase 存储 / 数据库
  ↓
文档解析 / OCR / LLM 分析
  ↓
云端任务结果
```

## 2. 技术选型

| 层级 | 方案 | 说明 |
|------|------|------|
| 前端 | Next.js，沿用 v5 `frontend/` | 部署到 CloudBase 云托管 |
| 后端 | Python FastAPI | 适合文档解析、OCR 编排和模型调用 |
| 运行环境 | CloudBase 云托管容器 | 需要 LibreOffice、PyMuPDF 等系统依赖 |
| 数据库 | CloudBase 数据库或 PostgreSQL | 保存任务、结果、反馈、日志摘要 |
| 文件存储 | CloudBase 云存储 | 临时保存上传文件和中间产物 |
| DOCX 解析 | python-docx 或 mammoth python | 提取段落和表格 |
| DOC 转换 | LibreOffice headless | `.doc` 转 `.docx` |
| PDF 解析 | PyMuPDF 优先，pdfplumber 备选 | 提取文本层、渲染页面图片 |
| OCR | 腾讯云 OCR API 优先 | 降低镜像体积和部署复杂度 |
| LLM | OpenAI Responses API 优先，兼容 Chat Completions 兜底 | 沿用 v5 Prompt 和 JSON Schema 结构化输出 |
| 导出 | 前端 ExcelJS 保留，后续可迁移后端 | v6 初期减少前端改动 |

## 3. CloudBase 部署依据

CloudBase 云托管支持托管任意语言和框架编写的容器化应用，适合部署 Next.js 前端和 FastAPI 后端。官方语言框架文档也提供了 Next.js 云托管部署方式，要求配置 Dockerfile 并监听 3000 端口。

需要遵守的关键限制：

| 限制 | 对 v6 的影响 |
|------|--------------|
| 云托管请求超时时间 60s | OCR 和模型分析不能做成长同步请求 |
| 云托管请求包体大小 20M | 文件上传必须限制 20MB，后续大文件改云存储直传 |
| 一个环境服务数量限制 | v6 初期只规划 `frontend-service` 和 `backend-service` 两个服务 |
| 服务之间可内网调用 | 前端服务可通过内网或环境变量访问后端服务 |

## 4. 服务划分

### 4.1 frontend-service

来源目录：

```text
frontend/
```

职责：

1. 合同上传工作台。
2. 批量任务列表。
3. 轮询后端任务状态。
4. 展示合同分析结果。
5. 导出 Excel。
6. 反馈管理。
7. 设置页和模型服务连通性测试入口。
8. 保存用户个人默认模型配置，并随任务提交给后端。

v6 主要改造：

| 当前文件 | 改造方向 |
|----------|----------|
| `frontend/app/page.tsx` | 移除浏览器端解析流程，改为上传文件并创建后端任务 |
| `frontend/lib/docx.ts` | 降级为旧逻辑或删除，由后端解析替代 |
| `frontend/lib/types.ts` | 增加后端任务、文件类型、解析质量字段 |
| `frontend/lib/local-db.ts` | 保留缓存，但主要数据从后端 API 获取 |
| `frontend/lib/backend-api.ts` | 封装 `/api/jobs`、轮询、结果查询、模型测试 |
| `frontend/app/api/analyze/route.ts` | 可保留兼容，v6 正式链路迁移到后端 |

### 4.2 backend-service

新增目录：

```text

  Dockerfile
  requirements.txt
  app/
    main.py
    config.py
    schemas.py
    routers/
      health.py
      jobs.py
      files.py
    services/
      job_service.py
      storage_service.py

      ocr_service.py
      llm_service.py
    parsers/
      docx_parser.py
      doc_parser.py
      pdf_parser.py
      image_parser.py
    workers/
      job_worker.py
```

职责：

1. 接收上传文件或云存储 fileId。
2. 创建合同解析任务。
3. 执行 DOC/DOCX/PDF/JPG/PNG 文本抽取。
4. 对扫描件调用 OCR。
5. 调用 LLM 生成结构化结果。
6. 保存任务状态、分析结果和错误信息。
7. 提供任务查询和结果查询接口。
8. 提供轻量管理员页面，用于全局模型配置和后端连通性测试。

## 7. 任务执行策略

CloudBase 云托管 HTTP 请求有 60 秒超时限制，所以 v6 不能把完整流程放在一次同步请求里。

推荐流程：

```text
POST /api/jobs
  ↓
保存文件，创建 job 记录
  ↓
返回 jobId
  ↓
后台 worker 执行 parse → OCR → LLM
  ↓
前端 GET /api/jobs/{jobId} 轮询
  ↓
完成后 GET /api/jobs/{jobId}/result
```

后台执行方式建议分两阶段：

| 阶段 | 实现方式 |
|------|----------|
| v6 初期 | FastAPI 接口创建 `BackgroundTasks` 或进程内任务池 |
| v6 稳定期 | 引入 Redis / Tencent CloudBase 队列 / 云函数触发器作为任务队列 |

初期进程内任务池要注意：

1. 服务实例重启可能导致任务中断。
2. 需要任务超时和失败恢复。
3. 生产化后应迁移到可靠队列。

## 8. 文档解析流程

### 8.1 DOCX

```text
读取 DOCX
  ↓
提取段落文本
  ↓
提取表格文本
  ↓
合并为 plainText 和 segments
```

推荐库：

```text
python-docx
mammoth
```

### 8.2 DOC

```text
保存原始 DOC
  ↓
LibreOffice headless 转 DOCX
  ↓
按 DOCX 流程解析
```

容器需安装：

```text
libreoffice
fonts-noto-cjk 或其他中文字体
```

### 8.3 PDF

```text
读取 PDF
  ↓
尝试提取文本层
  ↓
如果文本长度和有效字符比例达标：进入分析
  ↓
否则判定为扫描件
  ↓
渲染页面为图片
  ↓
调用 OCR
```

建议判断规则：

| 指标 | 建议阈值 |
|------|----------|
| 总文本长度 | 小于 300 字视为疑似扫描件 |
| 平均每页文本 | 小于 80 字视为疑似扫描件 |
| 中文/数字/英文有效字符比例 | 低于 30% 视为异常 |

### 8.4 JPG/JPEG/PNG

```text
读取图片
  ↓
可选压缩和方向校正
  ↓
调用 OCR
  ↓
合并 OCR 行文本
```

## 9. OCR 方案

v6 首选腾讯云 OCR API，而不是在容器内直接运行本地 OCR。

原因：

1. 减少 Docker 镜像体积。
2. 避免中文 OCR 模型部署和性能调优。
3. 降低 CloudBase 云托管启动和扩容压力。

OCR 服务封装：

```text
services/ocr_service.py
```

接口：

```python
class OcrService:
    async def recognize_image(self, image_bytes: bytes) -> OcrResult:
        ...

    async def recognize_pdf_pages(self, page_images: list[bytes]) -> OcrDocumentResult:
        ...
```

环境变量：

```text
TENCENTCLOUD_SECRET_ID=
TENCENTCLOUD_SECRET_KEY=
TENCENTCLOUD_OCR_REGION=ap-guangzhou
OCR_CONFIDENCE_WARNING_THRESHOLD=0.75
```

## 10. LLM 分析方案

v6 后端接管 v5 的 `/api/analyze` 能力。

迁移内容：

| v5 位置 | v6 位置 |
|---------|---------|
| `frontend/app/api/analyze/route.ts` | `backend/app/services/llm_service.py` |
| JSON Schema | `backend/app/schemas.py` |
| Prompt | `backend/app/services/llm_service.py` 中的 v6 Prompt |
| 模型配置 | 用户请求覆盖、管理员运行时配置、backend-service 环境变量 |

后端要求：

1. 优先使用 Responses API + JSON Schema。
2. 当兼容服务不支持 Responses API 或 JSON Schema 时，自动回退 Chat Completions JSON Schema，再回退普通 Chat Completions JSON 解析。
3. 模型返回不合法时重试一次。
4. 对超长文本做分段摘要或章节切分，不直接超过模型上下文限制。
5. 日志中不输出完整合同正文和 API Key。
6. 沿用 v5 的合同问题、付款计划、质保、置信度和原文片段结构，确保前端展示和导出可复用。

### 10.1 模型配置优先级

有效模型配置按以下顺序计算：

```text
用户个人模型配置
  ↓ 不存在或为空
管理员全局模型配置
  ↓ 不存在或为空
后端 .env / 云托管环境变量
```

| 来源 | 产生方式 | 持久化 | 说明 |
|------|----------|--------|------|
| 用户个人模型 | 前端设置页 localStorage，随 `/api/jobs` 表单字段提交 | 当前浏览器 | 只影响该用户后续上传分析 |
| 管理员全局模型 | `/admin` 页面保存 | `RUNTIME_CONFIG_PATH`，默认 `backend/data/model-config.json` | 所有没有个人配置的用户共用 |
| 环境变量 | `.env` 或 CloudBase 环境变量 | 部署平台 | 最终兜底 |

用户个人模型不写入后端全局配置，管理员全局配置不覆盖用户个人选择。

### 10.2 结果呈现结构

后端分析结果中的 `issues` 继续兼容 v5 字段，并允许补充 `suggestion`：

| 字段 | 说明 |
|------|------|
| `severity` | ERROR / WARNING / INFO |
| `category` | 问题分类 |
| `location` | 条款位置 |
| `description` | 问题描述 |
| `suggestion` | 修改建议，可由模型直接返回 |

前端按 `severity` 分表展示，并生成问题摘要表：

| 摘要列 | 说明 |
|--------|------|
| 风险等级 | ERROR / WARNING / INFO |
| 数量 | 当前等级问题数量 |
| 核心风险 | 当前等级的主要问题分类汇总 |

## 11. 前端改造方案

### 11.1 上传流程

当前 v5：

```ts
const contractText = await extractDocxText(file);
await fetch("/api/analyze", { body: JSON.stringify({ contractText }) });
```

v6：

```ts
const job = await createAnalysisJob(file, batchId, uploadIndex, llmSettings);
startPolling(job.jobId);
```

新增前端 API client：

```text
frontend/lib/backend-api.ts
```

函数：

```ts
createBatch()
createAnalysisJob(file, batchId, uploadIndex, modelSettings)
getJob(jobId)
getJobResult(jobId)
testBackendModel(modelSettings)
listBatches()
listBatchJobs(batchId)
```

### 11.2 设置页改造

前端设置页的模型配置改为“个人默认模型服务配置”：

1. 保存到当前浏览器 localStorage。
2. 上传文件创建任务时，将 API Key、Base URL、模型名作为可选字段提交到后端。
3. “测试连接”调用后端 `/api/model-test`，使用当前填写的模型配置测试后端实际分析链路。
4. 当用户未配置个人模型时，不阻塞上传，后端按管理员全局配置或 `.env` 兜底。

### 11.3 状态映射

| 后端状态 | 前端状态 |
|----------|----------|
| `created` | pending |
| `uploaded` | uploading |
| `extracting` | uploading |
| `ocr_processing` | uploading |
| `analyzing` | analyzing |
| `succeeded` | success |
| `failed` | failed |
| `cancelled` | cancelled |

### 11.4 本地缓存

IndexedDB 保留为体验优化：

1. 缓存最近批次和任务结果。
2. 网络失败时展示最后一次成功加载的数据。
3. 不再作为唯一历史来源。

## 12. 部署方案

### 12.1 CloudBase 服务规划

| `contract-analyzer-frontend` | `frontend/` | 3000 | Next.js 前端 |

### 12.2 frontend-service Dockerfile

当前 `frontend/Dockerfile` 已是 Next standalone 多阶段构建，可作为 v6 起点。部署到 CloudBase 云托管时设置端口：

### 12.5 部署步骤

1. 在 CloudBase 创建或选择环境。
2. 开启云托管按量计费。
3. 创建 `contract-analyzer-backend` 服务，选择 `backend/` 目录，端口 8000。
4. 配置后端环境变量和密钥。
5. 部署后访问 `/api/health` 验证后端可用。
6. 创建 `contract-analyzer-frontend` 服务，选择 `frontend/` 目录，端口 3000。
7. 配置 `NEXT_PUBLIC_BACKEND_API_BASE_URL` 指向后端服务域名。
8. 访问 `/admin?token=...` 配置或验证管理员全局模型，并执行连通性测试。
9. 前端部署后上传 DOCX、PDF、JPG、PNG 做端到端验证。
10. 绑定自定义域名和 HTTPS。
11. 配置日志、告警和文件清理任务。

## 13. 安全与隐私

| 项目 | 策略 |
|------|------|
| API Key | 用户个人密钥保存在当前浏览器并随任务提交；管理员密钥保存在后端运行时配置或环境变量；任何日志不得打印密钥 |
| 原始合同 | 存储路径按 jobId 隔离，默认 TTL 清理 |
| 日志 | 不打印完整合同正文，不打印密钥 |
| 上传校验 | 校验扩展名、MIME、文件大小 |
| OCR 结果 | 作为合同敏感数据处理，遵守同样 TTL |
| 跨域 | 只允许前端服务域名访问后端 API |
| 管理后台 | 必须配置强随机 `BACKEND_ADMIN_TOKEN`，生产环境只通过 HTTPS 访问 |

## 14. 错误码

| 错误码 | 说明 |
|--------|------|
| `UNSUPPORTED_FILE_TYPE` | 不支持的文件格式 |
| `FILE_TOO_LARGE` | 文件超过大小限制 |
| `UPLOAD_FAILED` | 文件上传失败 |
| `DOC_CONVERT_FAILED` | DOC 转换失败 |
| `PDF_PARSE_FAILED` | PDF 文本层解析失败 |
| `OCR_FAILED` | OCR 调用失败 |
| `NO_TEXT_EXTRACTED` | 未提取到可分析文本 |
| `MODEL_SERVICE_NOT_CONFIGURED` | 模型服务未配置 |
| `MODEL_ANALYSIS_FAILED` | 模型分析失败 |
| `OCR_NOT_CONFIGURED` | 扫描件解析需要 OCR，但后端未配置 OCR 服务 |
| `ADMIN_UNAUTHORIZED` | 后端管理接口 token 不正确 |
| `JOB_TIMEOUT` | 任务处理超时 |

## 15. 测试方案

### 15.1 样例文件

| 类型 | 样例 |
|------|------|
| DOCX | 现有采购合同模板 |
| DOC | 由 DOCX 另存为旧版 DOC |
| PDF 文本层 | 由 DOCX 导出的 PDF |
| 扫描 PDF | 图片扫描合成 PDF |
| JPG / PNG | 合同单页截图或扫描图片 |

### 15.2 核心测试用例

1. DOCX 上传、解析、分析、导出成功。
2. DOC 上传后转换成功并分析。
3. 文本层 PDF 不触发 OCR，分析成功。
4. 扫描 PDF 触发 OCR，分析成功。
5. JPG/PNG 触发 OCR，分析成功。
6. 非合同图片 OCR 成功但模型分析提示内容不足。
7. 超过 20MB 文件前端拦截。
8. 批量混合格式中单份失败不影响其他合同。
9. 后端模型服务未配置时返回明确错误。
10. 刷新页面后能重新加载云端任务结果。
11. 前端个人模型配置保存后，后续任务默认使用该配置。
12. 后端管理员全局模型配置可保存，并能通过管理页测试连通性。
13. 用户个人模型优先级高于管理员全局模型，管理员全局模型优先级高于 `.env`。
14. 合同问题按 ERROR、WARNING、INFO 分表展示，并生成问题摘要表。
