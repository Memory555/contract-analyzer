平台是什么
合同智能分析平台是一款面向合同审查人员的辅助工具，核心能力是把 DOCX 合同文件交给 AI 模型自动提取和检查，输出结构化的付款计划、质保明细和风险提示，降低人工逐页翻阅的成本。
🔍
合同分析
上传 DOCX → AI 自动提取付款计划（阶段、比例、时限）、质保明细（核心 + 扩展字段）、合同问题（error / warning / info 三级）；支持单份和批量（最多 20 份），串行执行、单份失败不影响其余
📊
导出中心
单合同 Excel 导出；批量汇总 Excel（5 个 Sheet：概览、付款计划、质保、问题、失败清单）
💬
反馈管理
对分析结果提交"有帮助"或"有问题"反馈；问题可选 5 种分类；另提供"我的云端总览"统计卡片 + 分页列表
⚙️
设置
配置模型服务（Base URL / API Key / 模型名）、联通测试、切换亮/暗色主题、清除本地数据
🆕
v5 新增：Skill 独立版本 —— 一个轻量级的命令行工具，用于偶尔分析 1-2 份合同，无需部署平台，可在各类 AI 工具中使用。详见「Skill 说明」标签页。

技术栈
层面技术说明
前端框架 Next.js 15（App Router）+ React 19 + TypeScript 单页多面板架构，Serverless API Routes 兼做后端
AI 调用 OpenAI SDK（Responses API + JSON Schema Structured Outputs） 兼容任何 OpenAI 协议的服务
DOCX 提取 mammoth.js 浏览器端提取，无需后端
Excel 导出 ExcelJS 前端直接生成，无需后端
云端数据库 Neon PostgreSQL（新加坡节点） 反馈数据持久存储 + 用户数据隔离
本地数据库 Dexie / IndexedDB 历史记录、导出记录、反馈提交状态缓存
容器化 Dockerfile（三阶段构建，standalone 输出） 部署到 CloudBase 云托管
Skill 版本 Node.js + mammoth + openai SDK 命令行工具，无需浏览器，跨平台运行

部署在什么平台

CloudBase 云托管读取 Dockerfile，构建 Docker 镜像
3
镜像以 Next.js standalone 模式运行，监听 3000 端口
4
CloudBase 提供公网访问地址，支持自定义域名

当前限制
v5 版本在 v4 平台基础上新增了 Skill 独立版本，以下是两个版本的共同限制和各自限制：

平台版本（v4）限制

限制项说明
环境 QPS标准版：500 QPS；企业版：1000 QPS
请求超时云托管统一 60 秒超时
请求包体最大 20 MB
数据库标准版为共享实例；企业版以上为独享实例

Skill 版本（v5）限制

限制项说明
仅支持单份不支持批量分析，每次只能分析一份合同
仅支持 DOCX不支持 PDF、DOC、扫描件（需先用其他工具转换）
需要 API Key用户需自行提供 OpenAI 或兼容服务的 API Key
无历史记录分析结果不保存，每次需重新分析

模型响应延迟

一次完整的合同分析流程中，延迟主要受以下因素影响：
📄 合同长度
文本越长，模型输入 token 越多，推理时间越长
5页 ≈ 5-10s · 20页 ≈ 15-30s
🧠 模型服务
不同模型 / 不同提供商的推理速度差异很大
GPT-4.1-mini: 3-8s/页
📝
总结：单份合同分析典型耗时 5-30 秒，主要由模型推理决定。Skill 版本为命令行工具，无浏览器开销，响应速度与平台版本相当。

快速验证步骤
平台版本验证步骤：
1
CloudBase 云托管中新建服务，上传 frontend/Dockerfile 并配置环境变量
2
等待构建完成（约 2-3 分钟）
3
访问服务公网地址，确认首页可打开
4
进入「设置」页面，点击「模型联通测试」确认 AI 服务可用
5
上传一份 DOCX 合同文件，执行分析，验证结果正常输出
Skill 版本验证步骤：
1
下载 skill 包并解压，进入 skill/ 目录，运行 npm install
2
配置 API Key：export OPENAI_API_KEY="your-key"
3
准备一份测试用 DOCX 合同文件
4
运行分析：node scripts/analyze.js --file 测试合同.docx
5
确认终端输出 Markdown 格式的分析报告，包含付款计划、质保明细和合同问题
