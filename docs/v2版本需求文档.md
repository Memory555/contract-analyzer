# 合同智能分析平台 v2 版本需求文档

版本：v2.0.0  
日期：2026-06-18  
状态：需求初稿  
基线版本：v1.0.0

## 1. 版本定位

v2 在 v1 单合同分析能力基础上，新增多合同批量分析与批量 Excel 导出能力。

v1 已完成的核心闭环为：

```text
上传单份 DOCX 合同 → 提取文本 → 调用模型分析 → 展示付款计划、质保明细、合同问题 → 导出单合同 Excel
```

v2 需要扩展为：

```text
上传一批合同 → 逐份分析 → 查看单合同和批量汇总结果 → 按用户选择导出 Excel
```

## 2. 目标与范围

### 2.1 版本目标

1. 支持一次上传多份合同，系统逐份完成分析。
2. 保留 v1 单合同分析体验，用户仍可只上传一份合同。
3. 支持批量任务状态跟踪，包括待分析、分析中、成功、失败。
4. 支持用户查看每份合同的独立分析结果。
5. 支持两类 Excel 导出：
   - 一个合同导出一个 Excel 文件。
   - 多个合同汇总导出到一份 Excel 文件，并能明确区分不同合同。
6. 对相同文件名、相同合同重复上传等情况，提供稳定区分方式，避免导出后混淆。

### 2.2 本期包含

| 模块 | 本期范围 |
|------|----------|
| 合同上传 | 支持多文件选择和拖拽上传 |
| 文件校验 | 对每份合同独立校验格式、大小、重复名称 |
| 批量分析 | 多合同逐份分析，展示每份合同状态和结果 |
| 结果查看 | 支持批量概览和单合同详情 |
| Excel 导出 | 支持单合同单文件导出、批量汇总导出 |
| 历史记录 | 本地保存批量任务和单合同结果，沿用 v1 本地存储思路 |

### 2.3 本期不包含

| 暂不包含 | 说明 |
|----------|------|
| 合同之间的语义对比 | v2 只做多合同批量分析，不做合同条款横向比价或差异分析 |
| 用户登录与权限 | 仍以轻量 Demo / 内部工具为主 |
| 云端任务队列 | 若本地批量耗时过长，再进入后续生产化阶段 |
| 在线编辑合同原文 | 只查看分析结果和原文片段 |
| 法律效力结论 | 仍定位为信息抽取和问题提示，不给法律结论 |

## 3. 用户场景

### 3.1 单合同快速分析

用户上传 1 份合同，系统按 v1 流程分析并展示结果，可导出该合同的 Excel。

### 3.2 多合同批量分析

用户一次上传多份合同，例如同一项目下的主合同、补充协议、不同供应商合同。系统逐份分析，并在任务列表中展示每份合同的处理状态、问题数量、付款条目数量、质保字段数量和整体置信度。

### 3.3 批量导出独立 Excel

用户希望把每份合同的结果分别交给不同负责人，因此选择“一个合同一个 Excel 文件”。系统为每份分析成功的合同生成独立 Excel。

### 3.4 批量导出汇总 Excel

用户希望进行统一汇总、筛选和后续跟进，因此选择“多个合同放在一张表”。系统将多份合同结果汇总到同一个 Excel 文件中，并在每行增加合同标识字段，确保同名合同也能区分。

## 4. 核心功能需求

### 4.1 多合同上传

**F-01 多文件上传**

| 项目 | 说明 |
|------|------|
| 触发 | 用户点击上传区域、多选文件，或拖拽多个文件 |
| 格式 | v2 初始沿用 v1，优先支持 DOCX；PDF / DOC 按后续技术确认扩展 |
| 单文件大小 | 默认单文件不超过 20MB |
| 单次数量 | 建议默认最多 20 份合同，可通过配置调整 |
| 校验粒度 | 每份文件独立校验，不能因某一份失败阻断全部文件 |
| 展示 | 上传后展示合同任务列表，包括合同显示名、文件名、大小、状态 |

**验收标准：**

- 一次选择 5 份 DOCX 文件后，页面生成 5 条待分析任务。
- 其中 1 份格式不支持时，仅该文件标记为失败，其余文件仍可继续分析。
- 上传同名文件时，列表中能看到不同的批次序号或上传序号。

### 4.2 合同唯一标识

**F-02 合同标识规则**

多合同场景下不能只依赖文件名区分合同。系统需要为每次上传的每份合同生成唯一标识。

| 字段 | 说明 | 示例 |
|------|------|------|
| 合同ID | 系统生成的唯一 ID，不展示给普通用户或低优先展示 | `c_20260618_001` |
| 批次ID | 同一次上传形成的批量任务 ID | `b_20260618_093012` |
| 上传序号 | 在当前批次中的顺序 | `001` |
| 原始文件名 | 用户上传文件名，保留扩展名 | `采购合同.docx` |
| 合同显示名 | 默认去除扩展名，可允许后续编辑 | `采购合同` |
| 导出合同编号 | 导出时使用的稳定短标识 | `001_采购合同` |

**同名处理规则：**

- 如果同一批次内存在相同文件名，列表和导出中必须增加序号。
- 如果用户重复上传同一份合同，也视为两条独立分析记录。
- 批量汇总 Excel 中每一行都必须包含“批次ID、上传序号、合同ID、合同名称、原始文件名”中的关键区分字段。

**验收标准：**

- 同时上传两个都叫 `合同.docx` 的文件，导出汇总表中能看到 `001_合同` 和 `002_合同`。
- 重复上传同一文件两次，系统保留两条记录，不自动覆盖。

### 4.3 批量分析任务

**F-03 批量分析执行**

| 项目 | 说明 |
|------|------|
| 分析方式 | 每份合同独立调用 v1 分析能力 |
| 执行策略 | 初期可串行处理，后续可配置并发数 |
| 状态 | 待分析、分析中、分析成功、分析失败、已取消 |
| 失败处理 | 单份失败不影响其他合同 |
| 重试 | 支持对失败合同单独重试 |
| 取消 | 支持取消尚未开始或正在分析的批量任务，具体可按技术可行性分阶段实现 |

**验收标准：**

- 批量任务中某一份合同分析失败，其他合同仍能展示成功结果。
- 失败合同有明确失败原因和“重试”入口。
- 批量任务完成后，页面显示成功数量、失败数量和总耗时。

### 4.4 批量结果概览

**F-04 批量结果列表**

批量分析完成后，页面需要展示合同级概览。

| 字段 | 说明 |
|------|------|
| 上传序号 | 当前批次内的序号 |
| 合同名称 | 默认来自文件名，可后续支持编辑 |
| 原始文件名 | 完整文件名 |
| 分析状态 | 成功 / 失败 / 分析中 |
| 问题数量 | 合同问题条数 |
| 付款条目 | 付款计划条目数 |
| 质保字段 | 核心字段 + 扩展字段数量 |
| 整体置信度 | v1 已有置信度 |
| 操作 | 查看详情、重试、导出单合同 Excel |

**验收标准：**

- 批量任务完成后，用户无需进入详情即可看到每份合同的风险概览。
- 点击某一合同后，进入该合同的 v1 结果详情视图。

### 4.5 单合同详情复用

**F-05 单合同结果详情**

v2 的单合同详情应尽量复用 v1 展示结构：

- 合同问题。
- 付款计划明细。
- 质保明细。
- 原文片段复核。
- 置信度。
- 单合同 Excel 导出。

差异在于详情页顶部需要增加当前合同在批次中的上下文：

| 字段 | 说明 |
|------|------|
| 批次ID | 当前合同所属批量任务 |
| 上传序号 | 当前合同在批次中的序号 |
| 合同名称 | 当前合同显示名 |
| 原始文件名 | 用户上传的原始文件名 |

## 5. Excel 导出需求

### 5.1 导出模式

**F-06 导出模式选择**

批量分析完成后，用户可选择以下导出模式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 单合同独立导出 | 每份合同生成一个 Excel 文件 | 分发给不同负责人逐份处理 |
| 批量汇总导出 | 多份合同结果汇总到同一个 Excel 文件 | 统一筛选、汇总和统计 |

如果浏览器不便一次性下载多个文件，单合同独立导出可分阶段实现为：

1. 用户逐个点击导出。
2. 系统打包为 ZIP 下载。

v2 初期可优先实现“逐个文件导出”和“批量汇总导出”，ZIP 打包可作为增强项。

### 5.2 单合同独立 Excel

**F-07 一个合同一个 Excel 文件**

每个合同的 Excel 结构沿用 v1：

| Sheet | 内容 |
|-------|------|
| 付款计划明细 | 当前合同的付款计划 |
| 质保明细 | 当前合同的质保字段 |
| 合同问题 | 当前合同的问题列表 |

文件命名规则：

```text
合同分析结果_{上传序号}_{合同显示名}.xlsx
```

示例：

```text
合同分析结果_001_采购合同.xlsx
合同分析结果_002_采购合同.xlsx
```

**验收标准：**

- 同名合同导出的文件名不会相互覆盖。
- 单合同 Excel 内只包含当前合同的数据。
- 单合同 Excel 打开后仍包含 v1 的三个 Sheet。

### 5.3 批量汇总 Excel

**F-08 多合同放在一份 Excel 文件**

批量汇总 Excel 文件命名规则：

```text
合同批量分析结果_{批次ID}.xlsx
```

推荐包含以下 Sheet：

| Sheet | 内容 |
|-------|------|
| 批量概览 | 每份合同一行，展示状态、问题数量、付款条目数、质保字段数、置信度 |
| 付款计划明细 | 多份合同的付款计划汇总 |
| 质保明细 | 多份合同的质保字段汇总 |
| 合同问题 | 多份合同的问题汇总 |
| 失败清单 | 分析失败或导出失败的合同列表 |

其中用户所说“多个合同放在一张表”可在产品上解释为：在同一个 Excel 文件中集中导出，并在各明细 Sheet 中用合同标识字段区分不同合同。如果业务方明确要求所有付款、质保、问题都放在单个 Sheet，也可增加“单 Sheet 汇总模式”，但默认不建议，因为字段差异较大，后续筛选和维护成本更高。

### 5.4 汇总 Sheet 字段

**批量概览 Sheet**

| 字段 | 说明 |
|------|------|
| 批次ID | 当前批量任务 ID |
| 上传序号 | 当前批次内序号 |
| 合同ID | 系统唯一 ID |
| 合同名称 | 合同显示名 |
| 原始文件名 | 上传文件名 |
| 分析状态 | 成功 / 失败 |
| 问题数量 | 合同问题数量 |
| 错误数量 | severity = error 的问题数量 |
| 警告数量 | severity = warning 的问题数量 |
| 付款条目数 | payment_plan 数量 |
| 质保字段数 | core_fields + extra_fields 数量 |
| 整体置信度 | overall confidence |
| 失败原因 | 如失败则填写 |

**付款计划明细 Sheet**

| 字段 | 说明 |
|------|------|
| 批次ID | 当前批量任务 ID |
| 上传序号 | 当前批次内序号 |
| 合同ID | 系统唯一 ID |
| 合同名称 | 合同显示名 |
| 原始文件名 | 上传文件名 |
| 阶段 | 付款阶段 |
| 阶段名称 | 付款阶段名称 |
| 支付比例 | 提取出的支付比例 |
| 付款描述 | 多条条件合并换行 |
| 支付时限 | 付款时限 |
| 备注 | 备注 |
| 涉及位置 | 合同条款位置 |

**质保明细 Sheet**

| 字段 | 说明 |
|------|------|
| 批次ID | 当前批量任务 ID |
| 上传序号 | 当前批次内序号 |
| 合同ID | 系统唯一 ID |
| 合同名称 | 合同显示名 |
| 原始文件名 | 上传文件名 |
| 字段 | 质保字段名 |
| 内容 | 字段内容 |
| 备注 | 备注 |
| 涉及位置 | 合同条款位置 |
| 字段类型 | 核心字段 / 扩展字段 |

**合同问题 Sheet**

| 字段 | 说明 |
|------|------|
| 批次ID | 当前批量任务 ID |
| 上传序号 | 当前批次内序号 |
| 合同ID | 系统唯一 ID |
| 合同名称 | 合同显示名 |
| 原始文件名 | 上传文件名 |
| 序号 | 当前合同内问题序号 |
| 问题类型 | 条款矛盾 / 数值缺失 / 逻辑冲突 / 定义模糊等 |
| 严重程度 | 错误 / 警告 / 提示 |
| 问题描述 | 问题说明 |
| 涉及位置 | 合同条款位置 |

**验收标准：**

- 汇总 Excel 中任意一行明细都能追溯到具体合同。
- 同名合同在汇总 Excel 中通过上传序号和合同ID区分。
- 有失败合同时，失败清单 Sheet 中展示失败原因，不影响成功合同导出。

## 6. 页面与交互需求

### 6.1 合同分析页

v2 的合同分析页应从“单文件上传”升级为“单文件 / 多文件统一入口”。

页面主要区域：

1. 上传区：支持单文件和多文件。
2. 批量任务列表：展示每份合同的状态。
3. 批量概览：展示总数、成功数、失败数、问题总数。
4. 单合同详情区：点击合同后展示 v1 详情。
5. 导出操作区：选择导出模式并下载。

### 6.2 导出中心

导出中心在 v2 中应从占位页面升级为可用页面，至少展示：

| 内容 | 说明 |
|------|------|
| 最近批量任务 | 批次ID、创建时间、合同数量、成功/失败数量 |
| 可导出结果 | 单合同导出、批量汇总导出 |
| 导出记录 | 文件名、导出时间、导出模式 |

### 6.3 状态文案

| 状态 | 推荐文案 |
|------|----------|
| 待分析 | 等待分析 |
| 分析中 | 正在分析 |
| 成功 | 分析完成 |
| 失败 | 分析失败 |
| 部分成功 | 部分合同分析完成 |
| 全部完成 | 批量分析完成 |

## 7. 数据结构建议

### 7.1 批量任务

```ts
type BatchAnalysisRecord = {
  batchId: string;
  createdAt: string;
  updatedAt: string;
  status: "pending" | "analyzing" | "partial_success" | "success" | "failed" | "cancelled";
  totalCount: number;
  successCount: number;
  failedCount: number;
  contractIds: string[];
};
```

### 7.2 合同任务

```ts
type ContractAnalysisRecord = {
  id: string;
  batchId: string;
  uploadIndex: number;
  fileName: string;
  displayName: string;
  exportName: string;
  fileSize: number;
  status: "pending" | "analyzing" | "success" | "failed" | "cancelled";
  createdAt: string;
  updatedAt: string;
  result?: AnalysisResult;
  errorMessage?: string;
};
```

### 7.3 兼容 v1

v1 的 `AnalysisResult` 结构可继续作为单合同分析结果结构。v2 只需要在外层增加批次、合同ID、上传序号、文件名等上下文字段。

## 8. 非功能需求

| 项目 | 要求 |
|------|------|
| 性能 | 单份合同仍以 10-30 秒为目标；批量总耗时按合同数量线性增长可接受 |
| 稳定性 | 单份合同失败不能中断整个批次 |
| 可追溯性 | 导出结果必须能追溯到具体合同和上传批次 |
| 数据安全 | 上传文件和分析结果默认保存在当前浏览器或临时环境，不长期云端存储 |
| 易用性 | 用户不需要理解合同ID，但导出中必须保留机器可识别标识 |
| 兼容性 | Chrome / Edge 最新两个大版本 |

## 9. 风险与待确认问题

| 问题 | 风险 | 建议 |
|------|------|------|
| 批量数量过多 | 模型调用时间和费用增加 | v2 默认限制单批最多 20 份 |
| 浏览器同时处理多文件 | 页面卡顿或内存占用高 | 初期串行分析，必要时限制并发 |
| 多文件下载 | 浏览器可能拦截连续下载 | 优先支持汇总 Excel；独立导出后续可做 ZIP |
| 同名合同 | 导出文件覆盖或汇总混淆 | 强制加入上传序号和合同ID |
| PDF / DOC 支持 | v1 目前主要支持 DOCX | v2 批量分析先基于 DOCX，格式扩展单独排期 |

## 10. 里程碑建议

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| M1 | 批量上传和任务列表 | 多文件上传、合同唯一标识、状态列表 |
| M2 | 批量串行分析 | 多合同逐份调用 v1 分析能力，支持失败隔离和重试 |
| M3 | 批量结果查看 | 批量概览、单合同详情切换、本地历史记录 |
| M4 | Excel 导出增强 | 单合同独立导出、批量汇总 Excel |
| M5 | 导出中心 | 批次记录、导出记录、重新下载入口 |

## 11. v2 验收清单

1. 可一次上传多份 DOCX 合同。
2. 每份合同都有独立状态，失败不影响其他合同。
3. 可查看任意一份合同的完整分析结果。
4. 可对任意成功合同导出单合同 Excel。
5. 可将多份成功合同导出为一份批量汇总 Excel。
6. 批量汇总 Excel 中每行都包含合同区分字段。
7. 同名合同、重复上传合同不会在页面或导出结果中混淆。
8. 批量任务完成后能看到成功数量、失败数量和失败原因。
9. 导出中心能看到最近批量任务和导出入口。
10. v1 单合同分析路径仍可正常使用。
