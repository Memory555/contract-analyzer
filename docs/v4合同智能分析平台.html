平台是什么
合同智能分析平台是一款面向合同审查人员的辅助工具，核心能力是把 DOCX 合同文件交给 AI 模型自动提取和检查，输出结构化的付款计划、质保明细和风险提示，降低人工逐页翻阅的成本。
🔍
合同分析
上传 DOCX → AI 自动提取付款计划（阶段、比例、时限）、质保明细（核心 + 扩展字段）、合同问题（error / warning / info 三级）；支持单份和批量（最多 20 份），串行执行、单份失败不影响其余
📊
导出中心
单合同 Excel 导出；批量汇总 Excel（5 个 Sheet：概览、付款计划、质保、问题、失败清单）
💬
反馈管理
对分析结果提交"有帮助"或"有问题"反馈；问题可选 5 种分类；另提供"我的云端总览"统计卡片 + 分页列表
⚙️
设置
配置模型服务（Base URL / API Key / 模型名）、联通测试、切换亮/暗色主题、清除本地数据
🧱
技术栈
层面技术说明
前端框架 Next.js 15（App Router）+ React 19 + TypeScript 单页多面板架构，Serverless API Routes 兼做后端
AI 调用 OpenAI SDK（Responses API + JSON Schema Structured Outputs） 兼容任何 OpenAI 协议的服务
DOCX 提取 mammoth.js 浏览器端提取，无需后端
Excel 导出 ExcelJS 前端直接生成，无需后端
云端数据库 Neon PostgreSQL（新加坡节点） 反馈数据持久存储 + 用户数据隔离
本地数据库 Dexie / IndexedDB 历史记录、导出记录、反馈提交状态缓存
容器化 Dockerfile（三阶段构建，standalone 输出） 部署到 CloudBase 云托管

当前限制

CloudBase 平台限制（当前使用标准版）

限制项说明
环境 QPS个人版 / 标准版：500 QPS；企业版：1000 QPS；企业高级版：可定制
请求超时云托管统一 60 秒超时，合同分析的模型调用也设为 60 秒上限
请求包体最大 20 MB
最大实例数单环境最多 28 个容器实例，达到上限后无法继续扩容
数据库个人版 / 标准版为共享实例；企业版以上为独享实例
💡
对于合同分析这种低频、长耗时请求的场景，500 QPS 已经远超实际需求。瓶颈不在并发接入，而在单次分析的模型响应时间。

模型响应延迟

一次完整的合同分析流程中，延迟主要受以下因素影响：
📄 合同长度
文本越长，模型输入 token 越多，推理时间越长
5页 ≈ 5-10s · 20页 ≈ 15-30s · 50页+ ≈ 30-60s
🧠 模型服务本身
不同模型 / 不同提供商的推理速度差异很大
GPT-4.1-mini: 3-8s/页 · DeepSeek v3: 中等
🌐 网络链路
请求经过 CloudBase → 公网 → 模型提供商
NIM(新加坡) → CloudBase(国内) 可能有跨境延迟
⏳ 冷启动
Neon 首次连接冷启动 + CloudBase 容器冷启动
非活跃期首次请求额外 1-5 秒
📝
总结：单份合同分析典型耗时 5-30 秒，主要由模型推理决定。批量分析为串行执行，20 份合同约需 2-10 分钟。

功能限制

📄
仅支持 DOCX
不支持 PDF、DOC、扫描件 OCR
👤
无登录体系
用户标识基于浏览器 UUID，换浏览器 / 清缓存后历史数据不可见
🔄
批量分析串行
一次分析完成后才处理下一份，无法并行
💾
历史记录本地存储
分析历史仅存于浏览器 IndexedDB，清除浏览器数据会丢失

快速验证步骤
1
CloudBase 云托管中新建服务，上传 frontend/Dockerfile 并配置环境变量
2
等待构建完成（约 2-3 分钟）
3
访问服务公网地址，确认首页可打开
4
进入「设置」页面，点击「模型联通测试」确认 AI 服务可用
5
上传一份 DOCX 合同文件，执行分析，验证结果正常输出
6
进入「反馈管理」→ 提交一条"有帮助"反馈，再查看「我的云端总览」确认数据写入 PostgreSQL
