## 一、平台是什么

合同智能分析平台是一款面向合同审查人员的辅助工具，核心能力是把 DOCX 合同文件交给 AI 模型自动提取和检查，输出结构化的付款计划、质保明细和风险提示，降低人工逐页翻阅的成本。

**四个功能模块：**

| 模块 | 做什么 |
|------|--------|
| **合同分析** | 上传 DOCX → AI 自动提取付款计划（阶段、比例、时限）、质保明细（核心 + 扩展字段）、合同问题（error / warning / info 三级）；支持单份和批量（最多 20 份），串行执行、单份失败不影响其余 |
| **导出中心** | 单合同 Excel 导出；批量汇总 Excel（5 个 Sheet：概览、付款计划、质保、问题、失败清单） |
| **反馈管理** | 对分析结果提交"有帮助"或"有问题"反馈；问题可选 5 种分类（漏条款 / 判断不准 / 风险等级不对 / 看不懂 / 其他）；另提供"我的云端总览"统计卡片 + 分页列表 |
| **设置** | 配置模型服务（Base URL / API Key / 模型名）、联通测试、切换亮/暗色主题、清除本地数据 |

## 二、技术栈

| 层面 | 技术 | 说明 |
|------|------|------|
| 前端框架 | **Next.js 15**（App Router）+ React 19 + TypeScript | 单页多面板架构，Serverless API Routes 兼做后端 |
| AI 调用 | **OpenAI SDK**（Responses API + JSON Schema Structured Outputs） | 兼容任何 OpenAI 协议的服务（OpenAI、NVIDIA NIM、DeepSeek 等） |
| DOCX 提取 | **mammoth.js** | 浏览器端提取，无需后端 |
| Excel 导出 | **ExcelJS** | 前端直接生成，无需后端 |
| 云端数据库 | **Neon PostgreSQL**（新加坡节点） | 反馈数据持久存储 + 用户数据隔离 |
| 本地数据库 | **Dexie / IndexedDB** | 历史记录、导出记录、反馈提交状态缓存 |
| 图标 | Lucide React | — |
| 容器化 | Dockerfile（三阶段构建，standalone 输出） | 部署到 CloudBase 云托管 |

**当前默认模型配置：**

- API Key: NVIDIA NIM（`nvapi-…`）
- Base URL: `https://integrate.api.nvidia.com/v1`
- 模型: `openai/gpt-oss-120b`

> 页面设置的模型配置优先级高于环境变量。用户可以在「设置」页面随时切换到 OpenAI 官方、DeepSeek 或其他兼容服务。

## 四、当前限制

### 4.1 CloudBase 平台限制（当前使用标准版）

| 限制项 | 说明 |
|------|------|
| **环境 QPS** | 个人版 / 标准版：**500 QPS**（每秒请求数）；企业版：1000 QPS；企业高级版：可定制 |
| **请求超时** | 云托管统一 **60 秒**超时，合同分析的模型调用也设为 60 秒上限 |
| **请求包体** | 最大 **20 MB** |
| **最大实例数** | 单环境最多 **28 个**容器实例，达到上限后无法继续扩容 |
| **数据库** | 个人版 / 标准版为共享实例；企业版以上为独享实例 |

> 对于合同分析这种低频、长耗时请求的场景，500 QPS 已经远超实际需求。瓶颈不在并发接入，而在单次分析的模型响应时间。

### 4.2 Neon PostgreSQL 限制（当前使用免费版）

| 限制项 | 免费版额度 | 影响 |
|------|------|------|
| **存储容量** | **0.5 GB / 项目** | 每条反馈记录含合同原文（通常数千字），预计可存 **数百条**反馈；超 0.5 GB 后项目暂停写入 |
| **计算时长** | 100 CU-hours / 项目 / 月 | 按约 0.25 CU ≈ 1 GB RAM 计算，约可连续运行 400 小时；5 分钟无活动自动暂停，恢复需要冷启动延迟（约 1-3 秒） |
| **网络出流量** | 5 GB / 项目 / 月 | 反馈读写流量极小，远不会触及 |
| **并发连接** | 连接池配置最大 10 个 | 低流量场景完全够用 |
| **自动暂停** | 5 分钟无写入后计算暂停 | 首次请求会有 1-3 秒冷启动恢复延迟 |

> **成本评估：** 免费版适合初期验证和小规模使用。若反馈量增大到需要更多存储，可升级至 Launch 版（$0.35/GB/月 + 按量计算费）或者改为 CloudBase 平台自带的PostgreSQL。

### 4.3 模型响应延迟

一次完整的合同分析流程中，延迟主要受以下因素影响：

| 因素 | 影响 | 典型值 |
|------|------|--------|
| **合同长度** | 文本越长，模型输入 token 越多，推理时间越长 | 5 页合同 ≈ 5-10 秒；20 页合同 ≈ 15-30 秒；50 页以上可能 30-60 秒 |
| **模型服务本身** | 不同模型 / 不同提供商的推理速度差异很大 | GPT-4.1-mini 较快（3-8 秒/页）；DeepSeek v3 中等；大型模型更慢 |
| **网络链路** | 请求经过 CloudBase → 公网 → 模型提供商 | NVIDIA NIM（新加坡）到 CloudBase（国内）可能有跨境延迟 |
| **模型并发排队** | 高峰时段模型 API 可能排队 | 延迟增加不可预测 |
| **冷启动** | Neon 首次连接冷启动 + CloudBase 容器冷启动 | 非活跃期首次请求额外 1-5 秒 |

> **总结：** 单份合同分析典型耗时 5-30 秒，主要由模型推理决定。批量分析为串行执行，20 份合同约需 2-10 分钟。

### 4.4 功能限制

| 限制 | 说明 |
|------|------|
| 仅支持 DOCX | 不支持 PDF、DOC、扫描件 OCR |
| 无登录体系 | 用户标识基于浏览器 UUID（localStorage），换浏览器 / 清缓存后历史数据不可见 |
| 批量分析串行 | 一次分析完成后才处理下一份，无法并行 |
| 历史记录本地存储 | 分析历史仅存于浏览器 IndexedDB，清除浏览器数据会丢失 |

## 五、快速验证步骤

1. CloudBase 云托管中新建服务，上传 `frontend/Dockerfile` 并配置环境变量。
2. 等待构建完成（约 2-3 分钟）。
3. 访问服务公网地址，确认首页可打开。
4. 进入「设置」页面，点击「模型联通测试」确认 AI 服务可用。
5. 上传一份 DOCX 合同文件，执行分析，验证结果正常输出。
6. 进入「反馈管理」→ 提交一条"有帮助"反馈，再查看「我的云端总览」确认数据写入 PostgreSQL。
