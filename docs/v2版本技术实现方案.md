# 合同智能分析平台 v2 版本技术实现方案

版本：v2.0.0  
日期：2026-06-18  
适用范围：前端开发、批量合同分析、Excel 导出、本地历史记录、Vercel / Cloudflare 部署

## 1. 实现目标

v2 在 v1 单合同分析基础上，新增多合同批量分析与批量汇总导出。

核心链路：

```text
多选、拖拽或分多次添加 DOCX 合同到待分析列表
  ↓
点击“开始分析”
  ↓
生成批次与合同任务
  ↓
逐份提取 DOCX 文本
  ↓
逐份调用 /api/analyze
  ↓
保存每份合同分析结果
  ↓
展示批量任务列表与当前合同详情
  ↓
在批量任务列表中导出单份合同 Excel，或在批量摘要中导出批量汇总 Excel
```

## 2. 技术边界

当前 v2 仍沿用 v1 的轻量前端架构：

| 项目 | 当前实现 |
|------|----------|
| 前端 | Next.js App Router |
| 文档解析 | 浏览器端 mammoth 解析 DOCX |
| 模型调用 | `/api/analyze` Serverless API |
| Excel 生成 | 浏览器端 ExcelJS |
| 历史记录 | IndexedDB + Dexie |
| 部署 | Vercel / Cloudflare Workers + OpenNext |

当前版本优先实现 DOCX 批量分析。PDF / DOC、扫描件 OCR、云端任务队列和用户权限仍不在本次实现范围内。

## 5. 合同唯一标识规则

v2 不再只用文件名识别合同。每份合同都会生成：

| 字段 | 用途 |
|------|------|
| `batchId` | 标识一次批量上传任务 |
| `uploadIndex` | 标识该合同在当前批次中的顺序 |
| `id` | 标识单份合同任务 |
| `fileName` | 原始文件名 |
| `displayName` | 页面展示名，默认去掉扩展名 |
| `exportName` | 导出用名称，格式为 `{上传序号}_{合同显示名}` |

同名文件示例：

```text
001_采购合同
002_采购合同
```

这样即使用户上传两个同名文件，页面列表和 Excel 汇总表也可以区分。

## 6. 批量分析执行策略

当前版本采用串行执行：

1. 用户选择一批文件。
2. 系统生成批次和合同任务列表。
3. 每份文件独立校验。
4. 校验失败的文件直接标记为失败。
5. 校验成功的文件按上传顺序逐份分析。
6. 单份合同失败只更新该合同状态，不中断后续合同。
7. 批次结束后统计成功数和失败数。

串行执行的好处是稳定、简单、对模型 API 压力小。后续如需加速，可增加可配置并发数，但需要处理浏览器内存、API 限流和取消任务问题。

## 7. 页面实现

### 7.1 合同分析页

合同分析页包含：

- 多文件添加区和待分析列表。
- 开始分析按钮。
- 批量摘要。
- 批量任务列表。
- 当前合同详情。
- 批量任务列表行内单合同导出。
- 批量汇总导出。
- 最近分析记录。

用户可一次选择多份合同，也可分多次选择合同。文件加入待分析列表后不会立即分析，只有点击“开始分析”后才会生成批次并逐份处理。用户只添加 1 份合同时，流程仍等价于 v1 单合同分析；添加多份时，页面显示整批任务状态。

### 7.2 批量任务列表

列表字段：

| 字段 | 说明 |
|------|------|
| 序号 | 当前批次内上传序号 |
| 合同名称 | 默认来自文件名 |
| 原始文件名 | 用户上传文件名 |
| 状态 | 等待 / 提取中 / 分析中 / 完成 / 失败 |
| 问题 | 合同问题数量 |
| 付款 | 付款计划条目数量 |
| 质保 | 质保字段数量 |
| 置信度 | 整体置信度 |
| 操作 | 查看详情 / 导出合同 / 重试提示 |

单合同导出入口放在批量任务列表的每一行中，不放在批量摘要区。批量摘要区只保留整批维度操作，例如“导出批量汇总”。

### 7.3 导出中心

导出中心展示：

- 最近批量任务。
- 当前批次导出入口。
- 导出记录。

当前批次可一键导出“全部合同汇总表”。

## 8. Excel 导出实现

### 8.1 单合同行内导出

函数：

```ts
exportAnalysisExcel(fileName, result, includeIssues, exportName)
```

文件名：

```text
合同分析结果_{上传序号}_{合同显示名}.xlsx
```

Sheet：

- 付款计划明细。
- 质保明细。
- 合同问题，可由用户选择是否包含。

### 8.2 批量汇总导出

函数：

```ts
exportBatchAnalysisExcel(batchId, contracts, includeIssues)
```

文件名：

```text
合同批量分析结果_{批次ID}.xlsx
```

Sheet：

| Sheet | 内容 |
|-------|------|
| 批量概览 | 每份合同一行，展示状态、问题数量、付款条目数、质保字段数、置信度 |
| 付款计划明细 | 所有合同的付款计划明细 |
| 质保明细 | 所有合同的质保字段 |
| 合同问题 | 所有合同的问题列表 |
| 失败清单 | 失败合同和失败原因 |

每个明细 Sheet 都包含合同区分字段：

```text
批次ID / 上传序号 / 合同ID / 合同名称 / 原始文件名
```

## 9. 本地存储升级

IndexedDB 数据库仍为：

```text
contract-analyzer-demo
```

v2 新增表：

| 表 | 主键 | 用途 |
|----|------|------|
| `batches` | `batchId` | 保存批量任务 |
| `contracts` | `id` | 保存每份合同任务和结果 |
| `exports` | `id` | 保存导出记录 |

保留 v1 的 `records` 表，用于兼容最近单合同分析记录。

## 10. 当前限制与后续增强

| 限制 | 说明 | 后续方向 |
|------|------|----------|
| 仅支持 DOCX | 沿用 v1 浏览器端 mammoth 解析 | 引入后端解析 PDF / DOC |
| 串行分析 | 稳定但慢 | 增加并发数配置和限流 |
| 重试需重新选择文件 | 浏览器不会持久保存原始 File 对象 | 引入临时文件存储或更清晰的重新上传流程 |
| 批量独立文件未打 ZIP | 当前重点是汇总 Excel | 增加 JSZip 打包 |
| 无云端历史 | 仍为轻量本地工具 | 后续引入用户、任务队列和数据库 |
