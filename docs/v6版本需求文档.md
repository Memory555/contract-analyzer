# 合同智能分析平台 v6 版本需求文档

版本：v6.0.0  
日期：2026-06-30  
状态：需求初稿  
基线版本：v5

## 1. 版本定位

v6 在 v5 的合同分析工作台、批量分析、导出中心、反馈管理和模型配置基础上，进入正式文档解析能力建设阶段。

v5 的核心链路仍以浏览器端 DOCX 解析为主：

```text
上传 DOCX 合同
  ↓
浏览器端 mammoth 提取文本
  ↓
Next.js API 调用模型
  ↓
展示结构化结果并支持 Excel 导出
```

v6 需要升级为：

```text
上传 PDF / DOC / DOCX / JPG / PNG 合同或扫描件
  ↓
CloudBase 后端创建解析任务
  ↓
后端完成格式转换、文本层提取、OCR 和质量检查
  ↓
调用模型生成结构化合同分析结果
  ↓
前端轮询任务状态并展示结果
  ↓
保存云端任务记录，支持导出和人工复核
```

## 2. 版本目标

1. 正式支持 PDF、DOC、DOCX、JPG、PNG 五类合同文件。
2. 支持扫描件合同，包括扫描 PDF 和合同图片。
3. 引入 CloudBase 前端 + CloudBase 云托管后端部署形态。
4. 将文档解析从浏览器端迁移到后端，降低前端内存和兼容性风险。
5. 使用异步任务机制处理超过 60 秒的解析、OCR 和模型分析流程。
6. 保留 v5 的批量分析、结果展示、Excel 导出和反馈管理能力。
7. 建立任务、文件、解析文本、分析结果、错误信息的云端可追踪记录。
8. 支持用户在前端设置个人默认模型，并在每次后端分析时优先使用该用户模型；管理员可配置全局模型作为兜底。

## 3. 本期范围

| 模块 | v6 范围 |
|------|---------|
| 文件上传 | 支持 PDF / DOC / DOCX / JPG / PNG，单批多文件上传 |
| 文档解析 | 后端解析 DOCX、DOC、PDF 文本层、扫描 PDF、JPG、PNG |
| OCR | 支持扫描件识别，优先接入腾讯云 OCR API |
| 异步任务 | 上传后创建任务，前端轮询状态，不阻塞请求 |
| 云端数据 | 保存任务状态、解析摘要、分析结果、失败原因 |
| 前端改造 | v5 工作台从本地解析改为后端任务驱动 |
| 模型配置 | 前端个人模型优先，后端管理员全局模型兜底，最终回退 `.env` |
| 后端管理 | 提供轻量后台管理页，支持全局模型配置和连通性测试 |
| 导出 | 继续支持单合同导出和批量汇总导出 |
| 部署 | 前端和后端均部署到 CloudBase 云托管 |

## 4. 不包含范围

| 暂不包含 | 说明 |
|----------|------|
| 法律意见结论 | 平台仍定位为信息抽取和风险提示，不替代法律审查 |
| 在线编辑原合同 | 只展示识别文本、原文片段和结构化结果 |
| 复杂版式还原 | v6 重点是文本抽取质量，不承诺完全还原 PDF/图片排版 |
| 多人权限体系 | 可预留用户字段，但 v6 不强制做组织、角色、审批流 |
| 本地离线 OCR | 优先云 OCR，后续再评估 PaddleOCR/Tesseract 本地化 |

## 5. 用户场景

### 5.1 上传可复制文本的 PDF 合同

用户上传电子版 PDF，系统优先提取文本层，不触发 OCR。若文本质量足够，直接进入模型分析。

### 5.2 上传扫描 PDF 合同

用户上传扫描版 PDF，系统发现文本层为空或极少后，将页面渲染为图片并逐页 OCR。OCR 完成后合并文本进入模型分析。

### 5.3 上传 JPG/PNG 合同图片

用户上传合同照片或扫描图片，系统直接 OCR，识别出文字后进入合同分析。

### 5.4 上传旧版 DOC 合同

用户上传 `.doc` 文件，后端使用 LibreOffice headless 转换为 DOCX，再按 DOCX 流程解析。

### 5.5 批量混合格式分析

用户一次上传多份合同，文件格式可以混合。系统为每份文件创建独立任务，单份失败不影响其他文件。

## 6. 功能需求

### 6.1 文件上传

**F-01 多格式上传**

| 项目 | 要求 |
|------|------|
| 支持格式 | `.pdf`、`.doc`、`.docx`、`.jpg`、`.jpeg`、`.png` |
| 单文件大小 | 默认不超过 20MB；超过时前端拦截并提示 |
| 单批数量 | 默认最多 20 份，可通过后端配置调整 |
| 上传方式 | 点击选择、多选、拖拽 |
| 校验粒度 | 每份文件独立校验 |
| 文件标识 | 每份文件生成 `contractId`、`jobId`、`batchId`、`uploadIndex` |

**验收标准：**

1. 可在同一批次中上传 PDF、DOC、DOCX、JPG、PNG。
2. 上传不支持格式时，仅该文件标记失败。
3. 上传超过大小限制的文件时，前端直接提示，不创建后端任务。

### 6.2 解析任务

**F-02 异步解析任务**

上传成功后，后端必须立即返回任务信息，前端不等待完整解析完成。

任务状态：

| 状态 | 说明 |
|------|------|
| `created` | 任务已创建 |
| `uploaded` | 文件已接收或已写入存储 |
| `extracting` | 正在提取文本或转换格式 |
| `ocr_processing` | 正在执行 OCR |
| `analyzing` | 正在调用模型分析 |
| `succeeded` | 分析完成 |
| `failed` | 任务失败 |
| `cancelled` | 用户取消或系统取消 |

**验收标准：**

1. 前端可看到每份合同当前处于哪一阶段。
2. 任务失败时必须展示失败原因。
3. 扫描件 OCR 时间较长时，页面不会卡死或请求超时。

### 6.3 文档解析

**F-03 多格式文本提取**

| 文件类型 | 处理方式 |
|----------|----------|
| DOCX | 解析段落、表格、页眉页脚中的文本 |
| DOC | 使用 LibreOffice headless 转 DOCX 后解析 |
| PDF | 优先提取文本层；文本过少时转 OCR |
| JPG/JPEG/PNG | 直接 OCR |

解析结果需包含：

| 字段 | 说明 |
|------|------|
| `plainText` | 合并后的合同文本 |
| `segments` | 按页、段落或表格切分的文本片段 |
| `sourceType` | `docx` / `doc` / `pdf_text` / `pdf_ocr` / `image_ocr` |
| `pageCount` | PDF 或图片页数 |
| `warnings` | 低置信度、空页、页码缺失等提示 |

**验收标准：**

1. 文本层 PDF 不触发 OCR，能进入分析。
2. 扫描 PDF 能触发 OCR 并进入分析。
3. DOC 文件能被转换并进入分析。
4. 解析不到有效文本时，任务失败并提示“未识别到可分析文本”。

### 6.4 OCR 识别

**F-04 扫描件 OCR**

v6 优先接入腾讯云 OCR API，不在首期自建 OCR 引擎。

OCR 识别要求：

| 项目 | 要求 |
|------|------|
| 输入 | PDF 页面图片、JPG/JPEG/PNG |
| 输出 | 页面级文本、行级文本、置信度 |
| 低置信度 | 低于阈值的页面需记录 warning |
| 失败处理 | 某页 OCR 失败时记录页码，允许整体任务按配置继续或失败 |

**验收标准：**

1. JPG/PNG 合同图片能识别并分析。
2. 扫描 PDF 至少能按页 OCR 并合并文本。
3. 低质量图片时页面展示“识别质量可能影响分析结果”。

### 6.5 模型分析

**F-05 结构化合同分析**

沿用 v5 的分析目标：

- 合同问题。
- 付款计划。
- 质保明细。
- 置信度。
- 原文片段。

v6 需要增加解析来源上下文：

| 字段 | 说明 |
|------|------|
| `sourceType` | 文本来自 DOCX、PDF 文本层还是 OCR |
| `extractionWarnings` | OCR 低置信度、文本过短、页缺失等 |
| `analysisPromptVersion` | 分析提示词版本 |
| `parserVersion` | 解析服务版本 |

**验收标准：**

1. v5 的结果展示组件能继续展示 v6 返回结果。
2. OCR 来源的分析结果要展示识别质量提示。
3. 模型输出不符合 JSON Schema 时，后端至少重试一次。
4. 用户在前端设置页保存个人模型后，后续上传分析默认使用该个人模型。
5. 未提供个人模型时，后端优先使用管理员配置的全局模型；管理员也未配置时，使用后端 `.env` 模型配置。

### 6.6 模型配置与连通性测试

**F-06 个人模型与全局模型**

v6 的模型配置分为两层：

| 层级 | 使用场景 | 保存位置 | 优先级 |
|------|----------|----------|--------|
| 用户个人模型 | 普通用户在前端设置页填写自己的 API Key、Base URL、模型名 | 当前浏览器 localStorage | 最高 |
| 管理员全局模型 | 管理员在后端管理页配置默认模型 | 后端运行时配置文件 | 中 |
| 后端环境变量 | 部署时提供兜底模型配置 | 后端 `.env` 或云托管环境变量 | 低 |

要求：

1. 前端个人模型配置不仅用于本地测试，也必须随 `/api/jobs` 任务提交给后端参与本次分析。
2. 个人模型配置保存后，在当前浏览器内成为默认配置，用户无需每次重新填写。
3. 管理员可通过 `/admin?token=...` 配置全局模型，并测试当前后端有效模型连通性。
4. 前端设置页的“测试连接”调用后端 `/api/model-test`，按用户当前填写的模型配置进行测试。

**验收标准：**

1. 前端个人模型配置存在时，后端分析使用个人模型。
2. 前端未传个人模型时，后端使用管理员全局模型。
3. 管理员全局模型未配置时，后端使用 `.env`。
4. 前端设置页和后端管理页均能发起模型连通性测试。

### 6.7 批量任务

**F-07 批量混合格式任务**

| 项目 | 要求 |
|------|------|
| 执行方式 | 每份合同独立任务，可限制后端并发 |
| 失败隔离 | 单份失败不影响其他任务 |
| 批次状态 | 根据单份任务聚合为待处理、处理中、部分成功、成功、失败 |
| 重试 | 支持对失败文件重新上传或基于已保存文件重试 |

**验收标准：**

1. 批次中 PDF 成功、JPG 失败时，批次显示部分成功。
2. 用户可查看每份合同的失败原因。
3. 批量汇总导出只汇总成功合同，并在失败清单中列出失败文件。

### 6.8 结果呈现、云端历史和反馈

**F-08 结果呈现和云端任务记录**

v6 需要从 v5 的浏览器本地历史，升级为云端任务记录。浏览器 IndexedDB 可继续作为缓存，但不能作为唯一数据源。

合同问题呈现要求：

| 区域 | 要求 |
|------|------|
| 问题明细 | 按 `ERROR`、`WARNING`、`INFO` 分组，每个等级单独展示表格 |
| 明细列 | 序号、问题分类、位置、问题描述、修改建议 |
| 问题摘要 | 增加摘要表格，按风险等级统计数量和核心风险 |
| 修改建议 | 优先使用模型返回的 `suggestion` / `recommendation` / `advice`，缺失时生成兜底建议 |
| 空状态 | 没有问题时展示“未发现明显问题”，避免空白 |

记录内容：

| 数据 | 是否保存 |
|------|----------|
| 原始文件 | 临时保存，按 TTL 清理 |
| 解析文本 | 保存，可配置脱敏或 TTL |
| 分析结果 | 保存 |
| 任务日志 | 保存关键节点，不保存完整密钥和敏感日志 |
| 用户反馈 | 保存 |

**验收标准：**

1. 刷新页面后仍可从云端加载最近任务。
2. 反馈管理能查看合同分析结果及必要的解析上下文。
3. 清理策略能删除过期原始文件。

## 7. 页面需求

### 7.1 合同分析页

v6 合同分析页需要从“DOCX 本地解析”调整为“云端任务工作台”。

页面区域：

1. 多格式上传区。
2. 待上传/已上传文件列表。
3. 批量任务进度。
4. 单合同任务状态。
5. 分析结果详情。
6. OCR/解析质量提示。
7. 导出入口。

主要文案更新：

| 位置 | v6 文案 |
|------|---------|
| 标题 | 上传 PDF / DOC / DOCX / JPG / PNG 合同并生成结构化分析结果 |
| 上传提示 | 支持电子文档和扫描件，单文件不超过 20MB |
| 解析中 | 正在解析合同文本，扫描件可能需要更长时间 |
| OCR 提示 | 当前文件疑似扫描件，正在进行 OCR 识别 |

### 7.2 设置页

设置页新增：

| 配置 | 说明 |
|------|------|
| 后端 API 地址 | 前端调用 CloudBase 后端服务的基础 URL |
| 个人默认模型 | 用户自己的 API Key、Base URL、模型名，保存后默认用于后续分析 |
| 模型连通性测试 | 调用后端 `/api/model-test`，验证当前个人模型是否可用 |
| OCR 开关 | 是否启用扫描件 OCR |
| 最大文件大小 | 展示后端配置，不建议由普通用户修改 |
| 数据保留说明 | 告知原始文件和解析结果的保存期限 |

### 7.3 后端管理页

v6 后端提供轻量管理页：

| 页面 | 说明 |
|------|------|
| `/admin?token=...` | 使用 `BACKEND_ADMIN_TOKEN` 保护的管理入口 |
| 全局模型配置 | 配置管理员默认 API Key、Base URL、模型名 |
| 后端模型测试 | 测试当前后端有效模型配置是否可连接 |
| 配置保存 | 保存到后端运行时配置文件，作为所有未配置个人模型用户的兜底 |

## 8. 非功能需求

| 项目 | 要求 |
|------|------|
| 稳定性 | OCR 和模型分析使用异步任务，不受 60 秒 HTTP 超时影响 |
| 性能 | 文本层文件优先走快速解析；扫描件按页 OCR |
| 可观测性 | 每个任务记录耗时、阶段、错误码 |
| 安全性 | 个人 API Key 仅保存在当前浏览器并随任务提交；管理员 API Key 保存在后端运行时配置或环境变量；日志不得输出密钥 |
| 隐私 | 原始文件默认短期保存，并提供清理机制 |
| 可扩展性 | 后端解析器按格式模块化，后续可增加 TIFF、Excel 附件等 |
| 成本控制 | OCR 和模型调用按页数、文本长度和批量数量限制 |

## 9. 风险与约束

| 风险 | 说明 | 对策 |
|------|------|------|
| CloudBase 请求超时 | 云托管请求超时为 60 秒 | 必须使用异步任务，长耗时步骤后台执行 |
| 请求包体限制 | 云托管请求包体大小为 20M | 前端限制大小，必要时改为云存储直传 |
| OCR 成本 | 扫描 PDF 页数多时成本高 | 增加页数限制和费用提示 |
| DOC 转换依赖 | LibreOffice 镜像体积较大 | 后端独立容器部署，前端不携带转换依赖 |
| 图片质量差 | 倾斜、模糊、遮挡会影响 OCR | 给出识别质量 warning 和人工复核提示 |
| 结果误判 | OCR 错字会传导到模型分析 | 分析结果标明来源和识别质量 |
| 个人密钥保存 | 用户个人模型密钥保存在浏览器 localStorage | 在设置页明确提示仅适合可信设备，生产期可升级为登录态加密存储 |
| 管理员配置持久化 | 初期运行时配置保存在容器文件系统 | CloudBase 生产部署建议挂载持久化存储或迁移到数据库/密钥管理 |

## 11. v6 验收清单

1. 已从 v5 创建 v6 分支并保留 v5 当前功能基线。
2. CloudBase 前端可访问合同分析工作台。
3. CloudBase 后端可创建任务并返回 jobId。
4. 可上传 PDF、DOC、DOCX、JPG、PNG。
5. 文本层 PDF、DOCX 可成功解析并分析。
6. DOC 可转换为 DOCX 并分析。
7. 扫描 PDF、JPG 和 PNG 可触发 OCR 并分析。
8. 前端可展示任务阶段、失败原因和解析质量提示。
9. 批量任务中单份失败不影响其他合同。
10. 分析结果可继续导出单合同 Excel 和批量汇总 Excel。
11. 原始文件和解析结果具备可配置清理策略。
12. 后端日志不输出 API Key 和完整敏感合同正文。
13. 前端个人模型、后端管理员全局模型、后端 `.env` 的优先级符合设计。
14. 前端设置页和后端管理页均能完成模型连通性测试。
15. 合同问题按 ERROR、WARNING、INFO 分表展示，并提供问题摘要表。
