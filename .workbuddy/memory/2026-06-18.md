## UI/UX 优化分析

对合同智能分析平台前端做了全面 UI/UX 审查。核心问题总结：
- 视觉：颜色扁平缺层次、阴影太浅、无暗色模式、排版层次只有2-3级
- 交互：几乎零过渡动画（sidebar折叠/drawer打开瞬间切换）、无hover/focus状态、无进度条/骨架屏
- 表格：无斑马纹、无行hover、无sticky header
- 空态：仅虚线框+灰色文字，缺乏引导
- 代码：1256行单文件架构、19个useState、prop drilling严重
- 无障碍：缺focus-visible ring、ESC关闭、aria属性、对比度不达标

最高ROI改动：过渡动画 + hover/focus状态 + 表格交互优化（纯CSS为主，工作量小但体验提升明显）

## 付款计划 & 质保明细展示优化

### 改动内容
1. **分析 prompt 更新**（route.ts）— 新增第 7 条语言要求：强制 LLM 输出简体中文阶段名/字段名，禁止中英混排或 camelCase
2. **付款计划展示简化**（AnalysisResultView.tsx）
   - `formatStage()` 函数：清理英文前缀（First/Second/Third stage），合并 stage + percentage 为「合同签订后预付款 30%」格式
   - 过滤掉 `percentage` 为 N/A 或含"发票"的通用说明行
3. **质保字段英→中翻译**（AnalysisResultView.tsx）
   - `warrantyFieldMap` 映射表覆盖 14 个常见英文字段名 → 中文（WarrantyPeriod→质保期、ResponseTimeMinor→一般故障响应时效 等）
   - `translateFields()` 自动翻译 core_fields 和 extra_fields
   - 未匹配的英文名保留原样（兜底）

## 合同问题中文化 + 全局缩放适配

1. **合同问题 type 英→中翻译** — `issueTypeMap` 映射 22 个英文类型名（ContradictoryTerms→条款矛盾、AmbiguousDefinition→定义模糊 等），`translateIssueType()` 翻译；prompt 也新增 type 中文要求
2. **全局缩放适配** — CSS `html { zoom: 0.8; }` 让页面默认以 80% 比例渲染，无需手动缩放浏览器
